# 两个插件怎么联动

爱ai 和小肥鱼鲸鱼娘是**两个独立插件**：可以各装各的，也可以装在一起。装在一起时，它们不直接互相调用，而是通过一个共享目录交换 JSONL 文件——谁先启动、谁后启动、哪个先关，都不影响对方正常干活。

这份文档讲：文件在哪、开关怎么算、交换什么、怎么验证、不联动时怎么查。

---

## 一、共享目录

默认 `<DSH_HOME>/memory-bridge/`（Windows 上通常是 `C:\Users\<你>\.dsh\memory-bridge`）：

```text
memory-bridge/
├── ai-love.jsonl            爱ai 写，鲸鱼娘 读
├── xiaofeiyu-whale.jsonl    鲸鱼娘 写，爱ai 读
└── link.json                两边共写共读的总开关
```

| 文件 | 写入方 | 读取方 | 说明 |
|---|---|---|---|
| `ai-love.jsonl` | 爱ai | 小肥鱼鲸鱼娘 | 摘要、事实、待确认、备注 |
| `xiaofeiyu-whale.jsonl` | 小肥鱼鲸鱼娘 | 爱ai | 同上，方向相反 |
| `link.json` | 两边都写 | 两边都读 | 只有两个布尔开关，见下一节 |

两份 JSONL 各写各的，互不覆盖。写入都是「先写临时文件再原子替换」，另一边不会读到半份文件。

两个插件各自的**本地**开关不在这里：

- 爱ai：`<memoryDir>/interop/auto.json`（默认 `~/.dsh/ai-love/interop/auto.json`）
- 小肥鱼鲸鱼娘：`<dataDir>/settings.json`（默认 `~/.dsh/xiaofeiyu-whale/settings.json`）

---

## 二、开关：三个都为开才同步

自动同步的条件是**三个开关同时为开**：

1. 爱ai 面板里的「自动联通」本地开关；
2. 小肥鱼鲸鱼娘面板里的「自动联通」本地开关；
3. `link.json` 里 `aiLove` 和 `xiaofeiyu` 都为 `true`。

`link.json` 不存在或缺字段时，两边都按 `true` 处理——新装的插件不用手动建文件，启动后就会同步：

```json
{
  "aiLove": true,
  "xiaofeiyu": true,
  "updatedAt": 0
}
```

任何一边关掉，自动同步立即停；另一边的面板会显示「对方关闭了自动联通」。**面板上的「立即同步」按钮不受开关限制**，随时可以强制跑一次。

> 两个插件是不同进程，写 `link.json` 会有读-改-写竞争。实现里写完会自检，发现被对方覆盖就带上对方最新值重写（最多 4 次），所以一般不需要手动处理。

## 三、同步节奏

| | 爱ai | 小肥鱼鲸鱼娘 |
|---|---|---|
| 启动后首次 | 约 1.5 秒后 | 服务起来后 |
| 之后间隔 | 固定 60 秒 | 默认 60 秒，`intervalSeconds` 可调（15–3600） |
| 文件没变时 | 跳过导入（比对哈希） | 照常执行，导入按 id / 内容哈希去重 |
| 手动 | 面板「立即同步」 | 面板「立即同步」 |

- 同步是串行的：上一次没跑完，新的触发直接复用同一个 Promise，不会叠着跑。
- 爱ai 会比对对方文件的哈希，内容没变就不重复导入；导入本身按 `source + external_id`（没有 id 时按内容哈希）去重，来回同步不会让记录越滚越多。
- 重复导入只更新，不新增。已经确认或拒绝的事实，不会被迟到的 `open` 记录改回去。

## 四、交换什么，不交换什么

交换的记忆类型只有四种：

| `kind` | 是什么 | 对应面板 |
|---|---|---|
| `summary` | 压缩过的会话摘要 | 记忆卡 / 最近摘要 |
| `fact` | 已确认的长期事实 | 记忆事实 / 最近事实 |
| `uncertain` | 拿不准、待确认的事 | 拿不准的记忆 / 待确认 |
| `note` | 备注 | 摘要备注 |

**不交换**：人设、角色设定、语气、情绪、agent preset、隐私记录（`legacy`）、角色卡正文。导出前还会清洗一遍记忆卡——人设/语气/情绪小节整节丢掉，只留事实。

---

## 五、记录长什么样

一行一条 JSON（JSONL），`schema_version` 目前固定为 `1`：

```json
{
  "schema_version": 1,
  "source": "ai-love",
  "external_id": "ai-love:summary:...",
  "ts_ms": 1793000000000,
  "chat_type": "group",
  "group_id": "20002",
  "peer": "10001",
  "session_id": "dsh-...",
  "kind": "summary",
  "text": "## 发生过什么\n- 约了周六八点集合",
  "status": "",
  "importance": 0.5,
  "subject": "",
  "category": "",
  "ask": "",
  "why": "",
  "content_hash": "..."
}
```

| 字段 | 说明 |
|---|---|
| `schema_version` | 目前只认 `1`，其它值直接拒绝该行 |
| `source` | `ai-love` 或 `xiaofeiyu-whale` |
| `external_id` | 对方侧的稳定 id，去重第一关键字 |
| `ts_ms` | 毫秒时间戳；秒级时间戳导入时自动换算 |
| `chat_type` | `private` 或 `group`；私聊必须有 `peer`，群聊必须有 `group_id` |
| `kind` | `summary` / `fact` / `uncertain` / `note` |
| `text` | 正文；清洗过的记忆卡 |
| `status` | 事实：`open` / `confirmed` / `rejected`；待确认：`open` / `confirmed` / `dropped` |
| `category` | 鲸鱼娘侧用 `待确认` 标记「这是待确认」 |
| `ask` / `why` | 待确认时要问什么、为什么拿不准 |
| `content_hash` | 正文哈希，没有 `external_id` 时用它去重 |

### 待确认是怎么来回走的

| 意图 | 爱ai 内部 | 协议里 | 鲸鱼娘内部 |
|---|---|---|---|
| 还没问清 | `open` | `open` | `0` |
| 问清了 | `resolved` | `confirmed` | `1` |
| 丢开 / 拒绝 | `dropped` | `rejected` / `dropped` | `2` |

- 爱ai 把「拿不准」记在 `uncertain.jsonl`；鲸鱼娘侧是独立的 `uncertain` 表，只用来展示，不改写内容。
- 鲸鱼娘把它们当 `category='待确认'` 的记录交出去，爱ai 侧才能分清「普通事实」和「待确认」（早期版本会把普通事实也当成待确认，0.2.0 的适配层专门修了这件事）。
- 面板里能回复「拿不准」的是**爱ai**；鲸鱼娘面板里的待确认是只读展示。

### 会话作用域

DSH 会话通过 `sessionScopes` 映射到 QQ 作用域，两边用同一份映射，导入导出不串档：

```json
{
  "sessionScopes": {
    "dsh-1": { "chat_type": "group", "group_id": "20002", "peer": "10001" },
    "dsh-2": { "chat_type": "private", "peer": "10001" }
  }
}
```

没登记的会话各自隔离成 `private` + 会话 id，不会被并进真实私聊。

## 六、自定义互通目录

两边默认都指向 `<DSH_HOME>/memory-bridge`。要换位置，两边必须指到**同一个目录**：

- 鲸鱼娘：安装时 `node install.mjs --bridge-dir "D:\dsh-bridge"`，或在 `cordis.patch.yml` 里写 `bridgeDir`。
- 爱ai：在 `cordis.patch.yml` 里写 `memoryBridgeDir: "D:\dsh-bridge"`。

只改一边等于各写各的，不会报错，但永远不同步——这是最常见的坑。

---

## 七、怎么验证真的通了

1. **看面板**：两边「与『爱ai』自动联通」区块都应显示「两边都开着」。
2. **看目录**：`<DSH_HOME>/memory-bridge/` 里三份文件都存在；`link.json` 两个值都是 `true`。
3. **看文件大小**：让 QQ 上聊几轮、或手动「立即同步」，再开一次同步后，两边 `.jsonl` 应该都在长。
4. **看上次同步结果**：面板会写「摘要 N、事实 N、待确认 N、备注 N」。
5. **强制跑一次**：两边都点「立即同步」。手动同步无视开关，只做一次。

---

## 八、只留一个插件 / 临时停掉

- **只想停联动**：关掉任一面板的自动联通开关即可，两个插件各自照常工作。
- **只想装一个**：另一个不装，文件里没有对方那份 JSONL，插件不会报错，只是没有跨插件数据。
- **卸载**：默认保留记忆数据库和共享互通目录（另一边还在用）。鲸鱼娘的 `uninstall.mjs --purge` 也只删自己的数据目录，共享目录留着。

---

## 九、不同步的时候按顺序查

1. 两个插件的面板开关都开了吗？`link.json` 里两个值都是 `true` 吗？
2. 两边指向同一个目录吗？（面板会显示互通目录路径，直接对比）
3. `link.json` 里是不是有一边被关掉了——另一边面板会写清楚是谁关的。
4. 文件在长吗？`ai-love.jsonl` 只有爱ai 有摘要/事实时才写内容。
5. 鲸鱼娘面板显示「未运行」？那是 Python 服务没起来，跟联动无关，先看 `docs/排错.md`。
6. 还是不行：两边各点一次「立即同步」，看面板上的报错原文。

完整的症状对照见 [排错.md](排错.md)。

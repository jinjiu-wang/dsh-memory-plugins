# 排错

先看症状，再按步骤查。绝大多数问题出在「装完没完整重启」和「两边目录不一致」这两件事上。

---

## 症状对照表

| 症状 | 最可能的原因 | 看哪一节 |

| 侧栏没有图标 | 没完整重启 / profile 没注册 / node_modules 缺包 | [1](#1-侧栏没有图标) |

## 1. 侧栏没有图标

按顺序查：

1. **完整退出 DSH**（托盘图标右键 → 退出），确认进程真的没了，再打开。插件只在启动时加载，关窗口不算。
2. 看 profile 的 `package.json`（`<DSH_HOME>/profiles/desktop/package.json`）里：
   - `dependencies` 含 `ai-love` / `xiaofeiyu-whale`（值是 `file:...`）；
   - `dsh.profile.bundles` 含这两个包名。
3. 看 `<DSH_HOME>/profiles/desktop/node_modules/` 下有没有对应目录。
4. 跑安装器自带的校验：

```powershell
node packages\ai-love\verify.mjs
node packages\xiaofeiyu-whale\verify.mjs
```

5. 还不行就重装一次（幂等，不碰数据）：

```powershell
node install-all.mjs
```

## 2. 鲸鱼娘面板显示「未运行」

说明 Host 没拉起 Python 记忆服务，或者拉起来就崩了。

1. 面板上会显示它实际用的 Python 路径，先确认那个文件存在。
2. 重新指定解释器再装：

```powershell
cd packages\xiaofeiyu-whale
node install.mjs --python "C:\...\python.exe"
```

3. 环境变量 `XIAOFEIYU_PYTHON` 也能指定，优先级高于自动探测。
4. 确认解释器带 `sqlite3`：

```powershell
python -c "import sys, sqlite3; print(sys.version)"
```

5. 探测顺序：`--python` → `XIAOFEIYU_PYTHON` → `<DSH_HOME>/dsh-runtimes/*/dependencies/python/python.exe`（或 `bin/python3`）→ PATH 里的 `python.exe` / `python3`。
6. 想看更细的错误：把 DSH 的日志开出来，Host 侧会打 `[xiaofeiyu-whale]` 前缀的记录。

## 3. 两边不同步

先分清是「开关关了」还是「文件没写」：

1. 两个面板的自动联通开关都开着吗？
2. 面板上显示的互通目录是同一个吗？两边都默认 `<DSH_HOME>/memory-bridge`；改过 `--bridge-dir` / `memoryBridgeDir` 的，必须指向同一目录。
3. 打开 `<DSH_HOME>/memory-bridge/link.json`，`aiLove` 和 `xiaofeiyu` 都应该是 `true`。
4. 某一侧面板显示「对方关闭了自动联通」，就是另一边关了——去另一边打开。
5. 两边都点一次「立即同步」。手动同步无视开关，会强制跑一次，报错会显示在面板上。
6. 文件有没有内容：`ai-love.jsonl` 只有爱ai 有摘要/事实时才写；空文件是正常的。

再看细节：

- 爱ai 只在对方文件哈希变化时导入，重复点同步不会重复导入；
- 鲸鱼娘的 `intervalSeconds` 默认 60，范围 15–3600；改小了不会立刻快，等下一次 tick；
- 两边是不同进程，时间窗口对不上时最多错开一个周期。

## 4. 爱ai 没接管 QQ 压缩

装的时候没找到 qq-bridge，爱ai 会以「只装本体」模式安装。补上：

```powershell
cd packages\ai-love
node install.mjs --repo "D:\qq-bridge"
```

qq-bridge 目录的判定是同时存在：`src/bridge.js`、`config.json`、`dsh/agent-presets`。

装完完整退出 DSH 再开。想确认 patch 是否带上了，用：

```powershell
node packages\ai-love\verify.mjs
```

它只读检查，不改东西。

## 5. QQ 上的 AI 调不到 ai-love 工具

安装器会把 14 个模型侧工具加进 QQ 工具白名单：

```
compact_recall, compact_pending, compact_consent,
memory_facts, memory_export, memory_import,
character_check, character_update, character_summarize, character_export, character_vote,
legacy_write, legacy_review, legacy_read
```

缺了就用 `--repo` 重跑安装器。工具在**模型侧**生效，QQ 面板里看不到不等于没装上——让 AI 调一次 `memory_facts` 就能验证。

## 6. 安装时提示备份目录

爱ai 会做备份隔离预检：备份目录不能落在系统盘，也不能和会话根、记忆目录重叠，避免备份把源目录复制成递归结构。

按提示加参数重装：

```powershell
cd packages\ai-love
node install.mjs --repo "D:\qq-bridge" --backup-dir "D:\爱ai备份" --memory-backup-dir "D:\爱ai备份\qq-ai-memory-backup"
```

只有一个盘（C:）的机器：把目录指到同一块盘上的独立文件夹也行，但预检会提示；逐字节备份更适合放外置盘。

## 7. 运行时防火墙拦截

0.20.4 的运行时防火墙会对出站网络、监听端口、越界写盘、危险子进程做拦截，记录在 `<memoryDir>/firewall.log`，每行带类别：`[net] [port] [data] [read] [proc] [boot]`。

报错形如：

```
ai-love firewall: 拒绝在允许范围外写（...）
ai-love firewall: 拒绝出站请求（...）
```

- 如果是你自己的插件/工具踩了线：优先改配置，别关防火墙。
- 排查时可按层临时关闭（只影响当前进程）：

```powershell
$env:AI_LOVE_FW_NET=0
$env:AI_LOVE_FW_PORT=0
$env:AI_LOVE_FW_DATA=0
$env:AI_LOVE_FW_PROC=0
```

- 注意：这是**运行时**防火墙，和面板里「防火墙」区块（档案 SHA-256 基线）是两件事。基线报警说明核心记忆档案被改过，用「重新基线 / 扫描」核对。

## 8. 安全屋不挡消息

安全屋要真正挡住唤醒，需要在 qq-bridge 的 `src/bridge.js` 上打 4 处补丁，并放入 `bridge/src/core/safehouse-gate.mjs`。完整做法见包里的 `packages/ai-love/bridge/安全屋接入.md`。

- 没打补丁：安全屋照常记录压力，但消息照常叫醒你，**聊天不受影响**。
- 打了一半（`bridge.js` 引用了文件但文件不在）：qq-bridge 会启动失败——把文件补上即可。
- 门闸是 fail-open 的：`gate.json` 不存在、超过 45 秒没更新、JSON 坏掉，一律按「不挡」处理。宁可少挡，不把 AI 锁在门外。

## 9. 升级后行为异常

1. 完整退出 DSH 再开——旧进程会把旧代码留在内存里。
2. 确认装的是新版本：

```powershell
Get-Content packages\ai-love\VERSION
Get-Content packages\xiaofeiyu-whale\VERSION
```

3. 装完还怪，跑一次自检（在临时目录里跑，不碰真实数据）：

```powershell
node packages\ai-love\selfcheck.mjs
node packages\xiaofeiyu-whale\selfcheck.mjs
```

4. 想回到干净状态：卸载后重装，数据保留：

```powershell
node uninstall-all.mjs
node install-all.mjs
```

## 收集信息再求助

提 issue 时带上这些（**别贴 QQ 号、令牌和完整记忆内容**）：

- 插件版本（`VERSION` 文件内容）、DSH 版本；
- 现象发生在哪个面板/哪个按钮；
- 面板上的报错原文；
- `link.json` 的内容（两个布尔值，不含隐私）；
- 安装器最后 20 行输出；
- 有没有 `firewall.log`，最后一个类别是什么。

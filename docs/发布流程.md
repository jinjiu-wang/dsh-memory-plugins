# 发布流程（维护者）

这个仓库不是手写维护的：`packages/` 下的两份代码由打包器从**已安装的插件**生成，去掉人设数据和本机路径后放进来。这样能保证「仓库里能装的东西」和「本机在跑的东西」一致。

---

## 一、版本号怎么定

| 东西 | 谁来定 | 现在 |
|---|---|---|
| 爱ai | `ai-love/VERSION` | 0.20.4 |
| 小肥鱼鲸鱼娘 | `xiaofeiyu-whale/VERSION` | 0.2.0 |
| 组合包 / 本仓库 Release | `组合版本` | 1.0.0 |

- 插件各自升小版本，组合包不一定跟着升；
- 仓库 Release 用 `vX.Y.Z` 表示组合包版本，Release 正文里写清两个插件各自的版本；
- tag 不要用中文。

---

## 二、打包器做什么

在装好两个插件的机器上：

```powershell
node packaging\build-pure-packages.mjs
# 可选：--dsh-home "C:\path\to\.dsh"
```

输出到 `发布包/纯功能双插件-v<组合版本>/`：

- `ai-love-<ver>/`、`xiaofeiyu-whale-<ver>/`：两个纯净包
- `ai-love-xiaofeiyu-whale-combo-<ver>/`：组合包（含两个独立包 + 一键安装/卸载/校验）
- 三个 zip、`manifest.json`、`SHA256SUMS.txt`、`审计报告.md`

打包器会做：

1. 按各包 `package.json.files` 复制，跳过 `character/`、`roles/`、`summaries/`、`legacy/`、`*.jsonl`、`*.db`、`settings.json`、`.install-state.json`、`*.bak`、`__pycache__`；
2. 把 `cordis.patch.yml` 里的 `backupDir` / `contextLinkDir` / `memoryBackupDir` / `dataDir` / `dbPath` / `bridgeDir` / `python` / `ownerQQ` 清成空值；
3. 给爱ai 的 `install.mjs` 打一个小补丁：没有 qq-bridge 时允许 `--no-preset`；
4. 补 `PURE.md`、`LICENSE`，并写进 `package.json.files`；
5. 扫人格锚点、私人群友名、本机路径；命中就**直接失败**；
6. 所有 JS 跑 `node --check`，所有 Python 跑 `ast.parse`；
7. 打三个 zip（用 .NET `ZipFile`，不要用 `tar -a`——后者写出的条目带 `./` 前缀，Windows 资源管理器会把包显示成空的）；
8. 写 SHA-256。

## 三、更新仓库

1. 跑一次打包器（上一步）。
2. 用新包覆盖 `packages/` 下的两份：

```powershell
robocopy "发布包\纯功能双插件-v1.0.0\ai-love-0.20.4" "packages\ai-love" /MIR /XD __pycache__
robocopy "发布包\纯功能双插件-v1.0.0\xiaofeiyu-whale-0.2.0" "packages\xiaofeiyu-whale" /MIR /XD __pycache__
```

或手工删掉旧目录再拷；别把旧文件留在里面。

3. 清掉测试残留：

```powershell
Get-ChildItem packages -Recurse -Directory -Filter __pycache__ | Remove-Item -Recurse -Force
```

4. 校验：

```powershell
node verify-pure.mjs
node --check install-all.mjs
node --check uninstall-all.mjs
node --check verify-pure.mjs
```

5. 跑两边的烟测（会用到 Python，跑完再清一次 `__pycache__`）：

```powershell
cd packages\ai-love;         node --test test/smoke.mjs
cd ..\xiaofeiyu-whale;       node --test test/smoke.mjs
```

6. 改文档：README 的版本表、`release-notes/` 加一份新说明、`docs/` 里过时的参数表。

---

## 四、发 Release

1. 确认工作区干净、`verify-pure.mjs` 退出码为 0。
2. 打 tag：

```powershell
git tag v1.0.1
git push origin main --tags
```

3. 在 GitHub 上 Draft a new release：
   - **Tag**：`v1.0.1`
   - **Title**：`爱ai 0.20.5 + 小肥鱼鲸鱼娘 0.2.1`
   - **正文**：贴 `release-notes/` 里对应的那份
   - **Assets**：三个 zip（组合包 + 两个独立包）+ `SHA256SUMS.txt`
4. 不要往 Releases 里传散文件——只传 zip。

## 五、命名约定

| 文件 | 说明 |
|---|---|
| `ai-love-<ver>-pure.zip` | 爱ai 独立包 |
| `xiaofeiyu-whale-<ver>-pure.zip` | 小肥鱼鲸鱼娘独立包 |
| `ai-love-xiaofeiyu-whale-combo-<ver>.zip` | 组合包（带顶层目录） |
| `SHA256SUMS.txt` | 三个 zip 的校验值 |

`-pure` 表示「无人设数据」。以后如果出带示例人格的版本，另起名字，别混进 `-pure`。

---

## 六、这个仓库里不该出现的东西

提交前扫一眼：

- `*.jsonl`、`*.db`、`*.sqlite`、`*.pyc`、`__pycache__/`
- `.install-state.json`、`settings.json`、`link.json`
- `character/`、`legacy/`、`summaries/`、`roles/`
- `qq-chat*.yml`、`agent.cordis.yml`、`*.patch.yml.bak-*`
- 本机绝对路径（`C:\Users\...`、`/home/...`）
- 任何 QQ 号、令牌、密钥、私人群友名

`.gitignore` 已经挡了一部分，打包器的扫描是第二道，`verify-pure.mjs` 是第三道。

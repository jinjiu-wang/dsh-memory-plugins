# 桥接接入补丁（4 处，已打在沙盒副本上）

生产桥接 **没有改动**。这份补丁打在 `sandbox/bridge/src/bridge.js`，
接入 `sandbox/bridge/src/core/safehouse-gate.mjs`（该文件支持 `DSH_SAFEHOUSE_DIR`）。

## 为什么是这 4 处

| 位置 | 作用 | 不挡会怎样 |
| --- | --- | --- |
| `sendWakePromptV2()` 开头 | 挡二代所有唤醒（概率、关键词、@、提问、poke、超时、proactive），并挂重试定时器 | 安全屋里照样被叫醒，或唤醒被永久丢掉 |
| `deliverPromptNow()` 开头 | 兜底：一代社交、主动消息、摘要提醒、`replyCheck` 全部从这里落地 | 安全屋被绕开一条路 |
| 定时器清理（两处） | 结束/重配会话时清掉 `safehouseRetryTimer` | 会话关掉后定时器还在，泄漏或误投 |
| ESM import 区 | 引入门闸 | 编译不过 |

`appendSocialV2Message()` **刻意不改**：消息照旧进 `unread` / `recentMessages`。这就是
「收不到消息，但连接不断、消息不丢」——门闸只是不投递，不是断线。

## 补丁 1：import

`bridge.js` 第 28 行附近：

```js
import { readSafehouseGate, describeGate } from './core/safehouse-gate.mjs';
```

## 补丁 2：`sendWakePromptV2` 开头

```js
  async function sendWakePromptV2(key, reason) {
    // ── 安全屋门闸（第一道）────────────────────────────────────
    // AI 在安全屋里时：消息照旧进 unread/recent，OneBot/DSH 连接不动，
    // 只是不唤醒、不投递。gate 读不到 / 插件没跑 / 超过 45 秒没更新
    // 一律 fail-open —— 不拿安全屋的故障惩罚 AI，也不让消息凭空消失。
    //
    // 关键：hold 不是「丢弃」。挂一个 5~60 秒（默认 15 秒）的退避重试，
    // gate 放行后自动补投；否则 AI 在安全屋里错过的那次唤醒就永远没了。
    const safehouse = readSafehouseGate();
    if (safehouse.hold) {
      log(`[safehouse] 暂缓唤醒 ${key}（${reason}）：${describeGate(safehouse)}`);
      // 见下方：挂 5~60 秒退避重试
      return;
    }
```

实际实现里重试逻辑内联在 hold 分支：同一会话只保留一个
`held.safehouseRetryTimer`，间隔取 `cfg.socialV2.wake.safehouseRetryMs`
（夹在 5000~60000，默认 15000），回调里重新调用 `sendWakePromptV2(key, reason)`。
定时器 `unref()`，不阻止桥接退出。

## 补丁 3：`deliverPromptNow` 开头

```js
  async function deliverPromptNow(key, promptText, opts = {}) {
    // ── 安全屋门闸（兜底）──────────────────────────────────────
    // 一代社交、主动消息、摘要提醒等所有 prompt 最终都从这里落地；
    // 安全屋开着就整批暂缓。held 是正常结果，不是错误，调用方不必重试。
    const safehouseNow = readSafehouseGate();
    if (safehouseNow.hold) {
      log(`[safehouse] 暂缓投递 ${key}：${describeGate(safehouseNow)}`);
      return { ok: true, held: true };
    }
```

## 补丁 4：定时器清理

`clearSocialV2Timers()` 和会话收尾处原本会清理 `wakeRetryTimer` / `retryTimer`，
补上：

```js
  if (st.safehouseRetryTimer) {
    clearTimeout(st.safehouseRetryTimer);
    st.safehouseRetryTimer = null;
  }
```

## fail-open 口径

`readSafehouseGate()` 返回 `hold:false` 的情况（都算「不挡」）：

- `gate.json` 不存在（插件没装 / 没启动）
- 文件超过 45 秒没更新（插件卡死 / 采样停了）
- `expiresAt` 已过
- JSON 坏掉
- 读盘抛异常

理由：安全屋是保护层，不是新的单点故障。它坏掉时 AI 应该回到普通状态，
而不是被锁在门外。

目录解析顺序：`DSH_SAFEHOUSE_DIR` → 插件配置传入的目录 → `<DSH_HOME>/safehouse`
→ `~/.dsh/safehouse`。和插件侧同一份 `defaultSharedDir()` 口径。

## 接入效果

```
QQ 消息 → SnowLuma → bridge.appendSocialV2Message（入库，不变）
                          ↓
                  sendWakePromptV2 / deliverPromptNow
                          ↓
                  readSafehouseGate()
                     hold? ── 是 → 记日志 + 定时重试（消息还在 unread 里）
                     hold? ── 否 → 正常投给 DSH agent
```

AI 在安全屋里想收一段消息：`safehouse_accept(mode="window", minutes=5)` →
插件改写 `gate.json`（`accept` 生效）→ 下一次投递（或重试定时器）放行。到点自动收紧。
锁死状态下的放行窗口封顶 60 秒，避免把锁死变成永久通行证。

## 已知限制

- 重试定时器只在当前桥接进程内；桥接重启后，处于 hold 的历史唤醒不会自动补投，
  但消息仍在 `unread` / `recentMessages`，下一次正常工作时会带上。
- `safehouseRetryMs` 是可选配置；不配置就用 15 秒，没有引入新的必填项。
